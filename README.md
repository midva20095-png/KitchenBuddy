# Кухонный помощник

Бот рецептов для сообщества ВКонтакте. Отвечает в личных сообщениях и в беседе, когда к нему обратились. Под постами не отвечает.

## Что умеет

- Две кнопки: «Поиск рецептов» и «Моя кулинарная книга».
- Поиск показывает рецепт по тексту как есть: `сырники на два человека`, `рецепт для диабетика`, `курица и рис`.
- «Сохранить» кладёт открытый рецепт в кулинарную книгу. В книге свои разделы: «Новый раздел», потом название, например «Завтраки».
- «Список по разделам» — общая книга для всех. Туда попадает рецепт, который человек положил в раздел. Разделы и рецепты открываются кнопками. Кнопку можно скрыть в админке.
- Уточнение к открытому рецепту: `замени сметану`.
- Если запрос про болезнь, бот даёт обычную домашнюю еду и пишет, что это не рекомендация врача.
- В конце ответа — короткая подпись с проектами. Если в каталоге второго сообщества нашёлся похожий мастер-класс или рецепт, перед проектами будет одна ссылка.

Фото бот не разбирает. Лечебных диет и опасных запросов не выполняет.

## Как подключён ВКонтакте

Бот ходит в сообщество ключом сообщества, не пользовательским. Связь — Bots Long Poll:

1. `groups.getLongPollServer` получает сервер, ключ и `ts`.
2. Бот ждёт события на этом адресе (`a_check`).
3. Новое сообщение уходит в `messages.send`. Под постами бот не отвечает.

При старте бот включает сообщения сообщества, кнопку «Начать», возможности ботов и событие `message_new`. Для этого у ключа нужно право «Управление сообществом» и «Сообщения».

В беседе бот отвечает, если в тексте есть «рецепт», имя бота, упоминание сообщества или это ответ на его сообщение. Обычный разговор людей он не перебивает.

## Как подключён GigaChat

Тот же контур, что у чата Сбера:

1. `POST https://ngw.devices.sberbank.ru:9443/api/v2/oauth` с заголовком `Authorization: Basic <ключ>` и телом `scope=...`. Заголовок `RqUID` — новый UUID на каждый выпуск токена.
2. Токен живёт около 25 минут. Дальше бот берёт новый. Если чат отвечает `401`, токен сбрасывается и запрос повторяется один раз.
3. `POST https://api.giga.chat/v1/chat/completions` с `Authorization: Bearer <токен>`, системной инструкцией повара и короткой историей диалога.

Ключ выпускается в [личном кабинете GigaChat](https://developers.sber.ru/studio). В переменную кладётся уже готовое значение Base64, с префиксом `Basic` или без него. Для личного ключа scope — `GIGACHAT_API_PERS`. Модель по умолчанию — `GigaChat-2`. Короткие имена `giga-lite`, `giga-pro`, `giga-max`, `giga-ultra` тоже понимаются.

У хоста авторизации Сбера сертификат часто не входит в набор CA контейнера, поэтому запросы к GigaChat идут через отдельный HTTPS-агент. К ВКонтакте это не относится: API ВК проверяется обычным образом.

На человека — 40 запросов к модели в московские сутки. Избранное, шаги и список покупок лимит не тратят. Комментарии под постами считаются отдельно и ещё ограничены 30 ответами сообщества в час.

## Переменные

Скопируйте `.env.example` в `.env` локально. На Railway те же имена задаются в Variables сервиса. В репозиторий ключи не кладутся.

| Имя | Зачем |
| --- | --- |
| `VK_GROUP_TOKEN` | Ключ сообщества |
| `VK_GROUP_ID` | Номер сообщества |
| `VK_SCREEN_NAME` | Короткий адрес, если есть: для ссылки `vk.me` |
| `VK_COMMUNITY_NAME` | Имя в тексте бота |
| `BOT_NAME` | Как бот представляется |
| `GIGACHAT_AUTH_KEY` | Ключ авторизации GigaChat |
| `GIGACHAT_SCOPE` | `GIGACHAT_API_PERS` или корпоративный scope |
| `GIGACHAT_MODEL` | `GigaChat-2` или короткое имя |
| `GIGACHAT_DAILY_LIMIT` | Лимит на человека в сутки, `0` снимает лимит |
| `WALL_REPLIES` | Ответы под постами выключены. `1` включает их |
| `CHAT_REPLIES` | `0` выключает ответы в беседах |
| `SUBSCRIBERS_ONLY` | `1` — ответ только подписчикам. `0` — всем. Сбой проверки не закрывает бота |
| `DATA_DIR` | Папка файла, если базы нет. На Railway лучше `/data` |
| `DATABASE_URL` | Адрес Postgres. На Railway подставляется ссылкой на базу |
| `ADMIN_PASSWORD` | Пароль страницы `/admin`. Сам пароль в репозиторий не кладётся |
| `PORT` | Порт HTTP. Railway подставляет сам |
| `SOURCE_GROUP_ID` | Сообщество-каталог. Пусто — «Баба Яга» `213938339`. `0` выключает |

Диалог, избранное и карточка клиента лежат в Postgres. Если `DATABASE_URL` нет, тот же диалог пишется в `DATA_DIR/kitchen.json`.

Похожие материалы читаются только из статей сообщества «Баба Яга» (`SOURCE_GROUP_ID`, по умолчанию `213938339`). Посты со стены, видео и товары не берутся, чтобы в ответ не попадал мусор. Бот в чат этого сообщества не подключается и туда не пишет. Если статья похожа на запрос, в конце ответа одна строка «Смотрите также» и ссылка. Свой файл `DATA_DIR/lessons.json` можно добавить рядом. Пока статей нет, бот рекомендацию не выдумывает.

## Что подключается дальше

Память клиентов лежит в PostgreSQL, если задан `DATABASE_URL`. На Railway он появляется сам, когда карточка Postgres соединена с сервисом KitchenBuddy. На каждого человека заводится карточка: id ВК, имя, короткое имя, фото, когда пришёл, когда писал, сколько сообщений и рецептов, сообщество и пометка «закрыт». Диалог и избранное лежат рядом, в `client_state`. Журнал `client_log` помнит рецепты, ответы, комментарии и просьбу вступить. Если базы нет, бот пишет тот же диалог в файл `kitchen.json` и в логе прямо говорит об этом.

Админка открывается по адресу `/admin` паролем `ADMIN_PASSWORD`. Там клиенты, избранное, журнал и рецепты, которыми поделились. Чтобы открыть её с компьютера, у сервиса KitchenBuddy должен быть домен в Railway → Settings → Networking.

Кнопка раздела сама рецепт не ищет. Человек открывает полку, например «Супы», и пишет конкретное блюдо. Бот отвечает «Ищу рецепт в базе» и смотрит общую таблицу `catalog_recipes`: рецепты всех людей, не только того, кто спрашивает. Готовый рецепт сам пополняет эту базу. Рецепт с полки «Супы» не попадёт в «Торты»: сравнивается раздел и соседние подразделы, плюс все слова названия. Свой текст из «Мой рецепт» пишется и в ленту «Поделились», и в эту базу. «Моя база» показывает последние рецепты общей базы.

Большая кнопка сообщества «Поиск рецептов» ведёт в чат с ботом. Её ставит мини-приложение KitchenBuddy, тем же способом, что кнопка в другом боте: приложение должно быть включено, добавлено в сообщество, а адрес приложения — `https://<домен сервиса>/app`. На компьютере откройте приложение из сообщества и нажмите «Поставить на страницу». Ключ сообщений эту кнопку не меняет.

Доступ подписчиков уже включён (`SUBSCRIBERS_ONLY=1`): перед ответом бот спрашивает `groups.isMember`. Неподписчику в личке и в беседе уходит ссылка на сообщество. Под постами бот отвечает по-прежнему. Если ВК не ответил на проверку, сообщение не теряется.

Второе сообщество — только каталог статей. Бот отвечает в KitchenBuddy, а из «Баба Яги» берёт одну похожую статью и дописывает ссылку «Смотрите также». Посты со стены не рекомендует. В чат `213938339` бот не устанавливается.

## Railway

1. [New Project](https://railway.com/dashboard) → Deploy from GitHub → репозиторий `KitchenBuddy`, ветка с этим кодом.
2. В Variables добавьте ключи из таблицы. `PORT` можно не задавать.
3. Соедините Postgres с сервисом KitchenBuddy: в переменных сервиса должна появиться ссылка `DATABASE_URL`. Тогда карточки клиентов переживут деплой. Без базы бот пишет диалог в файл, и он сотрётся при новом деплое.
4. Домен сервиса можно не показывать людям: бот сам ходит в ВК. Страница `https://<домен>/health` нужна Railway для проверки, что процесс жив. Она отвечает `200`, даже если ВК ещё переподключается.
5. Сборка берётся из `Dockerfile`, команда запуска — `node index.js`. Это уже записано в `railway.toml`.

После деплоя в логах должна появиться строка `ВК <номер> подключён, жду сообщения`. Если вместо неё отказ, текст скажет, чего не хватает: ключа, права «Управление» или включённого Long Poll.

Проверка в сообществе: написать боту «Начать», затем `борщ на 4`.

## Локально

```bash
npm install
cp .env.example .env
npm test
npm start
```

`http://127.0.0.1:8080/health` отвечает, даже если ключи ещё пустые. Пока нет `VK_GROUP_TOKEN`, процесс не подключается к сообществу и не падает.

## Команды в диалоге

`поиск рецептов`, `сохранённые`, `сохранить`, `меню`, `справка`, `открой 1`, `удали 2`.
